## 载荷格式（`organoid-geometry-v1`）

```json
{"format": "organoid-geometry-v1", "width": 200, "height": 200,
 "instances": [{"id": "i1", "class_key": "organoid", "polygon": [[x, y], ...],
                "confidence": 0.9}]}
```

`rect: [x0, y0, x1, y1]` 是等价简写。三条硬规则：

1. **格式串不匹配即拒**。容忍未知字段的读法会让新字段静默丢失，而"丢失"与"对端从未发送"在日志里不可区分。
2. **越界坐标即拒，不裁剪**。裁剪等于悄悄移动标注，之后所有指标测的都是移动后的版本。
3. **零面积实例即拒**。"这个对象不存在"应当由空 `instances` 表达，而不是由一个面积为 0 的实例表达——后者在下游是一个匹配失败的假阴性。

`submit_blind` 在**写入边界**解析载荷。一个指标层无法测量的产物会让仲裁在几天后卡住，而那时能改的人已经走了。

## 指标口径（PRD 6.1）

| 指标 | 取值 | 本仓库的约定 |
| --- | --- | --- |
| 检测一致性 | IoU ≥ 0.5 贪心一对一匹配 → F1 | 贪心而非匈牙利：阈值本身就是决策，按 IoU 降序取匹配更接近人工判读 |
| 逐对象 Dice/IoU | 匹配对上计算 | Dice = 2\|A∩B\|/(\|A\|+\|B\|)，像素中心采样（与 `morphometrics` 一致，避免半像素偏置） |
| HD95 / ASSD | 双向表面距离**合并**取 95 分位 | 不取两个方向分位数的最大值——那不是 Hausdorff 分布的 95 分位 |
| Krippendorff α | 名义量、允许缺测 | **少于两个可配对单元返回 `None`**：一个单元不是"一致"的小样本，而是没有证据；返回 0 或 1 都会被下游阈值当成数据 |
| 自助法区间 | 单元重采样，固定种子 `20261105` | PRD 4.5 要求可复现；时钟种子做不到 |
| 原始一致率 / 阳性·阴性一致率 | 分列报告 | 应对 Kappa 悖论：单一系数会掩盖"阳性一致但阴性不一致" |
| DET / TRA | 序列任务 | **未实现**：当前载荷是单帧几何，没有 track_id 语义。跨站点一致性同样未实现（联邦侧） |

## 争议度（composite-v1）

四项加权：`iou 0.50 / attribute 0.30 / confidence 0.10 / preannotation 0.10`。

- **权重是占位**，PRD 未给数。快照里同时写入 `controversy_profile` 与实际使用的权重，因此不同 profile 的分数不可比，且可事后重算。
- **缺失分量不按 0 计**。预标注本体尚无实体（M0 已记录的 `PreAnnotation` 缺口），置信度也不是每个客户端都送。缺失分量写进 `missing_components`，其余权重**重新归一**。把缺失当 0 会让"没有预标注"的样本显得更不争议，而复核触发条件正是争议度 Top 10%——于是触发与否取决于客户端恰好发了哪些字段。
- PRD 4.5 的验收"Top-20 命中率 ≥ 80%"**现在无法评估**：它需要首席的"确有争议"认定，即 M3 的 Adjudication。M3 落地后是一条回溯计算，不需要改这里的存储格式。

## 补充修订与指标集的关系（P-06）

`supplement()` 只写**新**修订（`revision_no=2`、`is_blind_read=false`、`derived_from` 指向盲读修订），盲读修订从此不再被写，P-06 因此在结构上成立而非靠约定。

**指标集只用盲读修订。** 补充修订产生于作者已看到他人结论之后，纳入 α 会把依赖性观测当作独立观测，数字看起来是一致性，实际测的是别的东西。所以补充修订**不触发**重算；它作为证据在仲裁视图里与盲读修订并列展示。

## 困难层（D-08 / Q-07）

`label_stratum()` 在入湖时打标，且只在样本进入盲读前允许——事后打标等于用标注结果去推断它本应预测的难度。

- **没有任何默认层**：信号缺失即拒绝（`StratumRuleError`），研究模板在 `publish` 时校验每个样本都有标签，缺失则发布失败。
- 系统只注册一个规则 `provisional_v1`，标记为 `provisional`，**必须显式 `allow_provisional=True` 才能使用**。Q-07 未定，规则信号与阈值都是占位；这样做的目的是让"我们在用一个未定案的规则"成为一次有署名、有 `rule_version`、有 `signal_snapshot` 的显式行为，而不是默认值。

## 读路径（P-01）

`view_task()` 是客户端唯一应当调用的读接口；`read_back()` 是给校验器的，**故意返回全部**，给客户端就是 MVP 那 11 处泄露的成因——"视图会过滤"不是控制。

- 投影在**数据层**执行：无权查看的段落**不出现**，而不是被置空。客户端收到 `None` 会学会容忍并渲染占位符，忘掉一个分支，占位符就变成了答案。
- 投影函数 `project_task()` 同时服务实时 API 与导出信封。两条路径若各写一遍，迟早对"谁能看什么"给出不同答案，而差异只会在渗透测试里被发现。
- **逐样本状态是入参**，不从 `Task.state` 聚合推导。一个进行中的任务本来就有样本处于不同阶段；用聚合状态推导会把揭示态载荷发给仍在盲读的样本。

## 这轮撞到的 PRD 冲突（需要拍板）

1. **3.2 与 4.5 冲突：揭示后领域专家能否看到另外两份修订。**
   3.2 权限矩阵写「查看他人盲读内容：领域专家 — 否」（无条件）；4.5 写「向三位专家同时揭示：模型预标注、三份修订、分歧区域高亮」。
   **M2 取更严的 3.2**：专家在揭示后仍只看到自己的修订与预标注可用性，看不到同伴修订、看不到分歧记录（分歧记录按 `peer_revisions` 权限一并收起）。理由：放宽一票否决项相关权限是最不该由实现方顺手做的决定。
   若改为 4.5 口径，改动点只有一处：`projection.visibility_for()` 给"持有该样本 Assignment 的领域专家"在非盲读阶段打开 `peer_revisions`（并让 `disagreement` 随之可见），其余代码不动。

2. **4.6 状态表要求 IN_REVIEW 的前置是「分歧分析已出」，但 12 条工作流边的 `begin_review` 守卫只有 `revealed`。**
   M2 在服务层补了这道检查：`reveal()` 在冗余 N ≥ 2 时先确保分歧记录存在，失败则拒绝揭示并说明原因。状态机本身不改——改边表要重算 110 个有序对，而这条约束是"揭示前先算"，属于服务编排而非状态可达性。

3. **`AWAITING_ADJUDICATION` 的入口（`request_adjudication`，守卫 `supplements_collected`）按 PRD 属于 S4，M2 未实现。** 补充修订的"收齐"因此还没有闭环动作；M3 需要新增一个事实列（`sample_states` 已是缓存，加列即可）与一次首席显式关闭窗口的操作。
